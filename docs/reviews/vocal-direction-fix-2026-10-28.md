# 主唱人声目标传递修复

用户试听反馈：《一跃山海开》v1 实际声音偏男声，与“空灵女声”设想不符。

## 原因与边界

女声要求原先在 references 和歌词结构摘要中，音乐请求主要依赖 LLM 编曲摘要；v1 总编曲说明没有明确女声主唱，仅少数段落提到女声。缺少在最终生成提示词中统一、独立、全曲贯穿的人声要求，也没有展示目标与实际听感的区别。文件质检只能验证格式、帧完整性、时长和部分声学特征，不能证明演唱类型、空灵程度或歌词准确性。

核对 [ACE-Step 官方协议](https://github.com/ace-step/ACE-Step-1.5/blob/main/docs/en/Openrouter_API_DOC.md)：caption 示例使用 female vocal；audio_config 没有独立 gender 字段。提示词控制仍是概率性约束，不能保证每次达到指定人声。

## 实现

- 新增 Pydantic VocalRequirements；Brief 可显式设置 vocals.lead 与 style，旧项目可从 references/constraints 推导，音频驳回意见可覆盖新版本目标。解析排除项时不会把“不要男声、男女对唱”当作男女混声要求。
- AudioAgent 将独立人声要求写入最终音乐提示词首尾，直接传入用户参考和创作约束，不能因编曲摘要遗漏而丢失女声目标。
- 对女声输出全曲 female lead、airy/ethereal/breathy、中文咬字和各段保持音色的方向；不增加服务商不支持的 gender 参数，不修改已批准歌词。
- 编曲提示同样接收人声目标；真实服务兼容入口复用同一解析逻辑。
- 每个版本原子保存 generation-intent.json，包含实际提示词和人声目标；恢复时如输入改变则阻断同版本重用，要求新版本，避免不知情重复生成。
- Composition 记录该版本人声目标；页面新增人声目标和试听说明，将歌词原稿的创作设想与成品表现区分。人工试听仍由用户决定，模型不能自行批准。
- 新 vocals 字段缺省时不参与既有 brief_digest，保留旧 checkpoint 身份和审核记录有效性。
